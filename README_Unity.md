# Unity-прототип DINO vs MONSTERS (grayboxing)

Версія Unity: будь-яка 2021 LTS або новіша (3D, шаблон 3D Core або Built-in).

## Налаштування за 5 хвилин

1. Створіть новий 3D-проєкт.
2. У папці Assets створіть папку Scripts і скопіюйте в неї 5 файлів:
   GameManager.cs, PlayerController.cs, Enemy.cs, Barricade.cs, Resource.cs.
3. Якщо Unity 6 або проєкт з New Input System і є помилка про Input:
   Edit > Project Settings > Player > Other Settings > Active Input Handling = Both.
4. На сцені створіть:
   - Plane (GameObject > 3D Object > Plane), Scale = (4, 1, 4). Це земля.
   - Cube з назвою Base, Position = (0, 1, -18), Scale = (4, 2, 3). Це база.
   - Cube з назвою Player, Position = (0, 0.5, -12). Прикріпіть скрипт PlayerController.
   - Порожній об'єкт GameManager (GameObject > Create Empty). Прикріпіть скрипт GameManager.
5. Камера: Position = (0, 28, -14), Rotation = (65, 0, 0).
6. Натисніть Play.

## Керування

| Клавіша | Дія |
| --- | --- |
| WASD / стрілки | рух |
| B | поставити барикаду (10 дерева, вдень) |
| R | полагодити барикаду поруч (5 дерева, вдень) |
| Space / ліва кнопка миші | стріляти (вночі) |

## Що перевіряє прототип

Один повний цикл: День (збір, будівництво) -> Ніч (2 хвилі) -> Підсумок -> ... -> Перемога після 3-ї ночі або Поразка, якщо база зруйнована.

## Де змінювати баланс

Числа в коді відповідають таблиці Баланс_DINO_vs_MONSTERS.xlsx:
- кількість ворогів у хвилях: масив waves у GameManager.cs;
- HP, швидкість, шкода ворогів: метод Spawn у Enemy.cs;
- шкода і влучність гравця: поля у PlayerController.cs;
- HP барикад: Barricade.cs.
Після кожного тесту змінюйте числа і в коді, і в таблиці, а зміну записуйте в «Журнал тестів».

## Що свідомо НЕ зроблено (для Частини 2)

Пастки, кастомізація, мультиплеєр, інші карти, нормальна графіка.

## Збірка для itch.io

File > Build Settings > WebGL (або Windows) > Build. Папку з білдом заархівуйте в ZIP і завантажте на itch.io (тип Kind of project: HTML для WebGL).

## Порада

Вороги йдуть до бази по прямій. Ставте барикади між спавном (угорі карти) і базою (внизу), щоб вони реально перекривали шлях. Це хороший момент для спостережень на тесті: чи розуміють гравці, куди ставити барикади.
